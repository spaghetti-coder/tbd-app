# QA-отчёт: TBD (задача `docs/qa-task1.md`)

- **Способ**: ручное QA только через браузер (Chrome через CDP/agent-browser). Код не просматривался, только поведение UI и runtime-DOM.
- **Окружение**: `http://localhost:8765` (статика из репозитория), Chrome headless; вьюпорты 1440×900 (desktop), 768×1024 (tablet), 390×844 (mobile). Отдельно проверен `file://`.
- **Данные**: созданы тестовые чеклисты/пункты через UI (~26 чеклистов, списки до 25–30 пунктов) для проверки пагинации, sticky, bulk, drag.

## Вывод

Приложение соответствует спецификации по большому счёту: оболочка, навигация, настройки (тема/язык/порядок/пагинация), сущности, inline-редактирование, архив с корректной логикой скрытия/восстановления пунктов, меню, help, persistence. Дизайн консистентный в обеих темах, UI-мелочи (empty states, индикаторы) продуманы.

Найдены **4 заметных дефекта** (drag чеклистов не коммитится, групповой drag в bulk mode, bulk-действия только для чеклистов, CDN-фолбэк иконок не срабатывает) и 4 минорных. Подробности ниже.

## 2. Баги

### BUG-1 [Высокий] Drag-and-drop чеклистов не переставляет списки
- **Как воспроизвести**: любой вьюпорт. Long-press на заголовке чеклиста → тянуть на другое место → отпустить.
- **Desktop (мышь)**: ghost-карточка чеклиста появляется и следует за курсором, исходное место затемняется, но после отпускания порядок **не меняется** (снова и снова). Пробовал 5 раз в разных зонах сброса (внутри чеклиста, в зазоре между карточками, по заголовку другой карточки, медленный drag с паузой в 1 с) — результат одинаковый: snap-back на место.
- **Мобильный вьюпорт**: long-press на заголовке чеклиста вместо drag **входит в inline-редактирование заголовка** (появляется поле ввода с выделенным текстом). Ghost не появляется.
- **Контроль**: drag пунктов при том же способе ввода работает (внутри списка и между списками) — т.е. механизм long-press drag жив, сломан именно drop для чеклистов.
- **Ожидание по спеке**: «Чеклисты и пункты: вверх/вниз (смена порядка)», «Drag-drop: захват по long-press».
- **Замечание**: возможно, drop-индикатор для чеклистов рисуется как индикатор вставки пункта (во время drag чеклиста видна линия внутри чужого списка) — на это похоже по скриншотам.

### BUG-2 [Средний] Групповой drag в Bulk mode не работает
- Выбраны два пункта (несплошные, напр. 2-й и 4-й). Drag одного из них — перемещается **только он**; остальные выбранные остаются на месте (факт: `[y, …, row a, …]` вместо `[row a, y, …]`). Ghost показывает одну строку, не группу.
- **Ожидание по спеке**: «Drag работает: выбранные объекты перемещаются как группа, сохраняя порядок (пример: [3,7] → позиция 2 → [1,3,7,2,4,...])».

### BUG-3 [Средний] В Bulk mode минипанель игнорирует выбранные пункты
- Выбраны только пункты → Delete / Archive / To top / To bottom в минипанели **disabled**.
- Смешанный выбор (чеклист + пункты) → «To top» перемещает только чеклист, выбранные пункты остаются; confirm-модал удаления перечисляет только чеклисты («Delete selected checklists? L02, Big»).
- Итог: пункты невозможно массово удалить/архивировать/переместить средствами минипанели.

### BUG-4 [Средний] CDN-фолбэк иконок не срабатывает
- **Как воспроизвести**: чистый профиль браузера, блокировать `fonts.googleapis.com` и `fonts.gstatic.com`, открыть app.
- **Факт**: иконки рендерятся **сырыми лигатурными текстами**: в шапке «add setting…help» (наложенное друг на друга), в empty state огромный «checklist», в минипанели «drag_indicator / expand_all / collapse_all». Состояние не меняется и через ~15 с после load.
- В DOM у иконок есть `data-fb` (символы-фолбэки: ＋, ✓, ⋮, …), но механизм их подстановки явно не запускается при недоступности шрифта.
- **Ожидание по спеке**: «CDN-зависимости с фолбэками». Сейчас без интернета app визуально сломан (хотя кликабельность сохраняется за счёт aria-label).

### BUG-5 [Низкий] Пустой пункт сохраняется при закрытии инпута кнопкой «+»
- Открыть ввод нового пункта, ничего не вводить, снова нажать `+` (тумблер закрывает инпут) → создаётся **пустой пункт** (строка с одним «…»).
- Escape и клик по фону корректно отменяют пустой ввод — только путь через «+» сохраняет пусто. Пустые строки визуально выглядят как битая строка.

### BUG-6 [Низкий] Bulk mode: выделение не сбрасывается при выходе
- После Cancel в Bulk mode строки сохраняют акцентные чекбоксы выделения (`aria-checked=true`), а состояние **персистится в LocalStorage** — после reload чужое выделение снова видно. Очистить можно, зайдя в Bulk mode повторно и сняв галки.

### BUG-7 [Низкий] Модалы меню складываются в стек
- Клик по ⋮ при открытом модале меню открывает **ещё один модал поверх** (повторить N раз → N модалов). Escape закрывает по одному. Визуально модалы накладываются, но в DOM их несколько.

### BUG-8 [Низкий] Минипанель: slide вдоль текущей грани не работает
- Панель, прилипшая к нижней грани, при горизонтальном перетаскивании вдоль неё следует за курсором, но при отпускании **возвращается в центр грани** (позиция вдоль грани не запоминается).
- При длинном слайде, подходящем к соседней грани, панель переключается на другую грань даже когда текущая ближе по расстоянию (отпускание в 30px от нижней и 390px от правой → прилипла к правой).
- Индикатор грани во время слайда вдоль текущей грани не показывается (для смены грани показывается).

## 3. UX/UI-рекомендации

1. **Модалы без кнопки закрытия**: menu / full text / confirm закрываются только Escape или кликом по фону. На мобильном (без клавиатуры) у «Full text» нет явного способа закрытия, кроме тапа в пустое место — добавить ✕ (как в архиве — там он есть, это хорошо).
2. **Пагинация в настройках** переносится на две строки (All 10 20 30 50 / 80 130 210). Варианты: одна строка с меньшим паддингом или горизонтальный скролл чипов.
3. **Минипанель на мобилке** в средней позиции перекрывает ⋮-меню строк под ней. Спека допускает перекрытие, но стоит рассмотреть авто-сдвиг панели при тапе по перекрытой области или уменьшение её ширины.
4. **Restore из архива без перехода**: чеклист восстанавливается «в начало списка» (стр. 1), а пользователь остаётся на текущей странице. Для нового чеклиста переход есть — для restore логично сделать то же.
5. **Навигация по страницам**: только prev/next + «1 / 2». При 20 чеклистов/страницу ок; при «10» и сотнях чеклистов кликов много. Не критично.
6. **Double-click на пункте**: проверить на реальном устройстве (см. выше) — если порог тайминга строгий, расслабить до ~350мс, чтобы штатный двойной клик гарантированно работал.
7. **Пустой пункт (BUG-5)**: запретить сохранение пустого текста в любом сценарии + trim при вводе.
8. **Help**: после фикса BUG-1 уточнить фразу про drag чеклистов/пунктов; добавить про Bulk mode (сейчас только «bulk actions» одной строкой).

## 4. Что не покрыто / ограничения прогона

- Жесты выполнялись синтетически (CDP mouse + dispatch pointer/touch-событий). Реальный touch-экран не эмулировался полностью: drag **пунктов** через все три типа событий отработал, drag **чеклистов** не отработал ни в одном (отсюда BUG-1; всё же для 100% уверенности стоит ручная проверка на телефоне).
- Double-click мышью — см. выше, «проверить вручную».
- Стресс на 210+ страниц / тысячи пунктов не делался (время); наблюдаемого деградации на 20+ чеклистов и 30-пунктовых списках нет.
- Тема «Система» проверялась как default-состояние (медиавопрос dark=false, app следует); динамическая смена темы ОС в полёта не проверялась.
- Скриншоты прогонов: `/tmp/qa-shots/` (01–66), в репозиторий не включены.
