## Баги

### BUG-1 [Высокий] — drag чеклистов не коммитится — **исправлено**
- **Корень**: сигнатура изменения цели в `recomputeTarget()` использовала `before.dataset.flipId`. У строк пунктов `data-flip-id` есть (на самой строке), а у чеклистов он висит на `.cl__head`, а не на секции `.cl` — для чеклистов сигнатура была всегда `"page|undefined"`. Первый (пустой) `flipMove` выполнялся, а все последующие смены цели отбрасывались: карточка физически никогда не двигалась → snap-back. Пункты работали, потому что у них ключ на месте.
- **Фикс**: ключ = `data-flip-id` (пункты) либо `s:<id>` секции (чеклисты); плюс страховочный сброс `G.lastSig` в `beginDrag()`.
- **Проверка**: T1 — перетащить чеклист в конец списка: порядок меняется (до: неизменён).

### BUG-2 [Средний] — групповой drag в bulk mode — **частично: ядро переноса работало, найдены 2 реальных дефекта — исправлены**
- Массовый перенос **пунктов** в обе стороны (вверх/вниз, внутри списка) воспроизведения не дал: T2/T3 pass ещё на нефиксированном коде (группа переносится вместе, порядок сохраняется, как в примере спеки).
- **Реальный дефект 1**: `commitClDrag()` вообще игнорировал группу — при bulk-drag чеклистов переезжал только перетащенный (T12 до фикса: второй выбранный оставался на месте). Теперь вся on-page часть группы встаёт на позицию дропа в текущем относительном порядке (вне-страничная часть группы остаётся, как и задумано пагинацией).
- **Реальный дефект 2**: ghost показывал одну строку, не группу (отметка QA). Теперь ghost — стопка элементов группы в порядке, в котором они лягут; все участники группы в списке приглушены (`drag-src`).
- **Проверка**: T12 (чеклисты), T2/T3 (пункты); DOM ghost = `[A, P24]`, `drag-src` = оба участника; скриншот 04.

### BUG-3 [Средний] — bulk-действия «только для чеклистов» — **не воспроизведено, поведение по спеке**
- В item-bulk (вход через ⋮ пункта) панель Delete/Archive/To top/To bottom активна и работает: T4 (To top → `[i2,i4,i1,i3]`), T5 (Archive → confirm «Archive selected items?», 2 пункта в архиве).
- Описанный QA сценарий соответствует **checklist-bulk** режиму: там у пунктов стоят обычные done-чекбоксы (не selection) — это по спеке («Область: пункты — только текущий чеклист»; selection-чекбоксы у пунктов появляются только в item-bulk). Клик по done-чекбоксу помечает выполнением, а не выбирает; «смешанный выбор» чеклистов+пунктов по дизайну невозможен (область bulk — одного типа), поэтому confirm-модалы и To top оперируют чеклистами — корректно.

### BUG-4 [Средний] — CDN-фолбэк иконок не срабатывает — **исправлено**
- **Корень**: `document.fonts.check()` по спецификации возвращает `true` сразу, как только *начинает* загрузку шрифта (даже если CDN заблокирован и шрифт никогда не загрузится) — опросный цикл всегда считал шрифт «на месте».
- **Фикс**: ждать `document.fonts.ready` (разрешается после завершения/провала загрузки, включая блокировку CSS) и проверять наличие семейства «Material Symbols Outlined» в наборе; плюс страховочный таймер 6 с. `applyIconFallback()` идемпотентен, иконки, созданные после фолбэка, сразу рендерятся глифами.
- **Проверка**: копия app со шрифтовым CSS → 404: `data-iconfb=1`, иконки шапки `＋ ⚙ ⓘ`, empty-state `☰`, новая иконка после фолбэка `⌄`. При живом CDN фолбэк не включается (webfont грузится).

### BUG-5 [Низкий] — пустой пункт/чеклист через повторное «+» — **исправлено** (+ UX-7)
- **Корень**: `addItem`/`addChecklist` создавали новую сущность **до** закрытия открытого инпута; следующий `renderList()` → `commitPendingEdit()` замыкал инпут на **новый** `ui.editing` со значением **старого** (пустого) инпута — новая сущность удалялась, а старая пустая оставалась в state и LS.
- **Фикс**: в `addChecklist`/`addItem` сначала `commitPendingEdit()` (сохранить набранное / удалить пустой fresh), потом создавать новую. UX-7 закрывается вместе с этим: пустой текст в любом сценарии не сохраняется (`commitEdit` trim'ит; fresh+пусто → сущность удаляется; существующая, отредактированная до пусто → сохраняет старый текст).
- **Проверка**: T6/T6b (пункт), T7/T7b (чеклист): после второго «+» ровно одна пустая сущность с открытым инпутом; Escape → список пуст.

### BUG-6 [Низкий] — выделение не сбрасывается при выходе из bulk — **не воспроизведено**
- Cancel в панели очищает выделение (T8: selbox 2 → 0, `aria-checked` исчезают). Выделение живёт в `ui.bulk`, а **не** в `state` — в LocalStorage ничего не пишется (T8: нет `bulk`/`ids` в LS), после reload выделения нет (T9). Чистый профиль и повторные входы в bulk проверялись.

### BUG-7 [Низкий] — модалы меню складываются в стек — **исправлено**
- `openMenu()` теперь сначала закрывает все открытые модалы: menu-модал не может лечь поверх другого (повторный клик по ⋮ заменяет модал, а не добавляет).
- **Проверка**: T10 — открыл menu, синтетический клик по другому ⋮ → в DOM ровно 1 модал (до: 2).

### BUG-8 [Низкий] — minipanel: slide вдоль грани — **исправлено (позиция), остальное не воспроизведено**
- **Корень**: для граней top/bottom позиция вдоль грани не сохранялась — `layoutPanel()` всегда центрировал панель по колонке, поэтому после отпускания панель возвращалась в центр.
- **Фикс**: новая настройка `settings.panelX` (аналог `panelY` для left/right): сохраняется при отпускании, применяется в `layoutPanel()` с клампом по вьюпорту.
- **Не воспроизведено**: (а) «прыжок на другую грань» — в тестах ближайшая грань выигрывает корректно, включая слайд вдоль текущей (T11: bottom остаётся bottom, без перехода на right; случай QA «30px от низа» при длинном списке согласуется со спекой «грани **списков**, не края страницы» — низ списка мог быть за экраном); (б) индикатор грани показывается и во время слайда вдоль текущей грани (T11 `hintShownDuringSlide: true`) — вероятно, визуальный недосмотр в прогоне.
- **Проверка**: T11 — панель прилипла к bottom, слайд вправо на 300+ px → после отпускания позиция вдоль грани сохранена (Δ < 40px), грань не сменилась.

## UX-рекомендации (1, 4, 5, 7)

1. **✕ в модалах** — добавлено в menu / full text / confirm (`.modal__titlebar` + `.modal__close`, как в архиве). Закрытие confirm по ✕ действие **не** выполняет (U1: `notDeleted: true`). Help-модал оставлен без ✕ (его в рекомендации нет).
4. **Restore из архива с переходом** — восстановленные чеклисты идут в начало списка, поэтому после restore `ui.page = 0` (аналог создания нового чеклиста). U3: был на стр. 2 → restore → на стр. 1, восстановленный чеклист сверху, архив-оверлей остаётся открытым (можно восстанавливать дальше).
5. **Навигация по страницам** — вместо «1 / 2» окна нумерованных кнопок с многоточиями: `‹ 1 2 … 6 ›` (текущая — акцентом, `aria-current="page"`), окно сдвигается с текущей страницей (проверено на 105 чеклистах / 6 страницах). Prev/next на месте.
7. **Пустой текст** — закрыт фиксом BUG-5 (см. выше): в любом сценарии пустое/пробельное значение не сохраняется, ввод trim'ится.
